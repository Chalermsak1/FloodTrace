# แหล่งกำเนิดข้อมูลและสายการแปรรูป (DATA PROVENANCE)
**ขอบเขตระบบ:** แพลตฟอร์ม FloodTrace จังหวัดปราจีนบุรี  
**สถานะการตรวจสอบ:** ร่างฉบับตรวจสอบเพื่อการใช้งานจริง (AUDIT READY)  
**วันที่ตรวจสอบล่าสุด:** 2026-10-02  

---

## 1. ที่มาของข้อมูลคืออะไร (What is Data Provenance)
ในระบบ FloodTrace คำว่า **"ที่มาของข้อมูล (Provenance)"** หมายถึง บันทึกประวัติและสายการเดินทางของข้อมูลทุกชิ้นตั้งแต่จุดกำเนิด เพื่อให้ผู้ใช้งานสามารถตอบคำถามสำคัญ 5 ข้อได้อย่างชัดเจนเสมอ:
1. **ข้อมูลนี้มาจากไหน?** (หน่วยงานใด หรือเครื่องมือใดเป็นผู้ผลิต)
2. **เก็บข้อมูลเมื่อไร?** (ระบุวันเวลาและระดับความสดใหม่ของข้อมูล)
3. **ข้อมูลถูกแปลงอย่างไร?** (ผ่านการคำนวณ ตัดทอน หรือจัดกลุ่มด้วยวิธีใด)
4. **ผ่านแบบจำลองอะไร?** (ใช้สูตรคณิตศาสตร์หรือแบบจำลองอุทกวิทยาใด)
5. **แสดงต่อสาธารณะอย่างไร?** (ข้อมูลดิบ ข้อมูลอนุพันธ์ หรือข้อมูลที่ผ่านการปกป้องความเป็นส่วนตัว)

## 2. ลำดับชั้นและประเภทข้อมูล 10 ระดับ (Data Categories & Verification Tiers)

เพื่อให้ประชาชนและเจ้าหน้าที่เข้าใจความหมายของข้อมูลอย่างถูกต้องตรงกัน ระบบ FloodTrace ได้แบ่งระดับข้อมูลออกเป็น 10 ประเภท พร้อมคำอธิบายและตัวอย่างที่เข้าใจง่าย:

| หมวดหมู่ข้อมูล | คำอธิบายภาษาไทย | ตัวอย่างในระบบ | ความหมายต่อการใช้งาน |
|---|---|---|---|
| **`FACT`** | ข้อเท็จจริงพื้นฐานที่ตรวจยืนยันได้ทางกายภาพ | วันเวลา พิกัดแม่น้ำสายหลัก | ข้อมูลอ้างอิงที่มีความแน่นอนสูงสุด |
| **`OFFICIAL_RECORD`** | บันทึกทางการจากหน่วยงานรัฐ | ทะเบียนโรงงานของกรมโรงงานฯ ปี 2563 | มีอยู่จริงตามสารบบราชการ แต่ไม่สะท้อนสถานะการปนเปื้อน |
| **`MEASURED_FACT`** | ค่าที่วัดได้จริงจากเครื่องมือตรวจวัดทางกายภาพ | ระดับน้ำ 4.50 เมตร รทก. จากสถานีโทรมาตร | เป็นค่าจริง ณ จุดตรวจวัด ไม่ใช่การคาดเดา |
| **`DERIVED`** | ข้อมูลที่คำนวณต่อยอดจากข้อมูลจริง | ระยะห่างทางภูมิศาสตร์ 350 เมตร จากโรงงานถึงแม่น้ำ | ได้จากการคำนวณทางเรขาคณิต (GIS) |
| **`MODELED`** | ผลลัพธ์จากแบบจำลองทางคณิตศาสตร์หรืออุทกวิทยา | การจำลองทิศทางการไหลของน้ำต้นน้ำ-ปลายน้ำ | เป็นการประเมินตามสมมติฐาน ไม่ใช่การยืนยัน 100% |
| **`FORECAST`** | ข้อมูลคาดการณ์สภาพอากาศล่วงหน้า | คาดการณ์ปริมาณฝน 45 มม. ในอีก 48 ชั่วโมงข้างหน้า | ใช้สำหรับเตรียมความพร้อม มีความไม่แน่นอนตามธรรมชาติ |
| **`CITIZEN_REPORTED`** | รายงานข้อสังเกตจากประชาชนในพื้นที่ | ชาวบ้านแจ้งพบน้ำมีกลิ่นเหม็น หรือน้ำเปลี่ยนเป็นสีดำ | เป็นข้อมูลเบาะแสภาคสนามที่ยังไม่ได้ตรวจในห้องแล็บ |
| **`UNVERIFIED`** | ข้อมูลที่ยังไม่ผ่านการตรวจพิสูจน์โดยเจ้าหน้าที่ | รายงานประชาชนที่เพิ่งส่งเข้ามาในระบบ | ห้ามนำไปใช้อ้างอิงเป็นข้อเท็จจริงเด็ดขาด |
| **`OFFICIAL_CONFIRMED`** | ข้อมูลที่ได้รับการตรวจยืนยันและรับรองผลทางการ | ผลตรวจแล็บ คพ. ยืนยันค่าสารเคมีเกินมาตรฐาน | สามารถใช้เป็นหลักฐานทางราชการได้ |
| **`INSUFFICIENT_DATA`** | ข้อมูลที่มีอยู่ยังไม่เพียงพอสำหรับการสรุปผล | ไม่มีผลตรวจสารเคมีในน้ำผิวดิน ณ บริเวณดังกล่าว | ต้องแสดงความว่างเปล่าอย่างซื่อตรง ไม่สร้างข้อมูลทดแทน |

## 3. ตัวอย่างการไหลของข้อมูลในระบบ (Data Lineage Examples)

### ตัวอย่างที่ 1: การจำลองการเชื่อมต่อทางน้ำ (Hydrological Reach Tracing)
1. **ต้นทาง:** กรมทรัพยากรน้ำสำรวจแนวลำน้ำหลัก (`dwr_waterways`) $\rightarrow$ สถานะ: `OFFICIAL_RECORD`
2. **การแปลง:** แปลงเส้นกึ่งกลางแม่น้ำให้เป็นโครงข่ายกราฟเชื่อมต่อ (Directed Reach Graph) $\rightarrow$ สถานะ: `DERIVED`
3. **การคำนวณ:** ระบบคำนวณการไหลย้อนทวนน้ำจากจุดที่ผู้ใช้เลือก เพื่อค้นหาลำน้ำที่เชื่อมต่อกัน $\rightarrow$ สถานะ: `MODELED`
4. **การแสดงผล:** แสดงผลบนแผนที่พร้อมระบุคำเตือน: *"นี่คือการจำลองการเชื่อมต่อทางน้ำ มิใช่การยืนยันการไหลของสารปนเปื้อน"*

### ตัวอย่างที่ 2: การรายงานของประชาชนและการปกป้องความเป็นส่วนตัว (Citizen Observation)
1. **ต้นทาง:** ประชาชนถ่ายภาพและกรอกรายงานผ่านมือถือในตำบลท่าตูม $\rightarrow$ สถานะ: `CITIZEN_REPORTED`
2. **การปกป้องข้อมูล:** ระบบตัดข้อมูล EXIF และเบลอพิกัด GPS ละเอียดจาก $(13.98765, 101.76543)$ เหลือเพียงทศนิยม 2 ตำแหน่ง $(13.99, 101.77)$ หรือระยะประมาณ 1.1 กิโลเมตร $\rightarrow$ ป้องกันการระบุบ้านพักอาศัย
3. **การแสดงผล:** แสดงสัญลักษณ์บนแผนที่พร้อมป้ายกำกับสีส้ม **`UNVERIFIED (ยังไม่ได้รับการยืนยัน)`**

## 4. โครงสร้างเมทาดาตาของข้อมูล (Provenance Metadata Schema)

ทุกอ็อบเจกต์ข้อมูลใน API จะแนบโครงสร้าง Provenance ดังนี้:

```json
{
  "agency": "สำนักงานสิ่งแวดล้อมและควบคุมมลพิษที่ 7 (สคพ.7) / คพ.",
  "dataset": "ผลการตรวจวัดคุณภาพน้ำผิวดินลุ่มน้ำปราจีนบุรี",
  "category": "INSUFFICIENT_DATA",
  "source_verification": "VERIFIED_OFFICIAL",
  "timestamp": "2026-10-02T12:00:00Z",
  "unit": "มิลลิกรัมต่อลิตร (mg/L)",
  "crs": "EPSG:4326 (WGS84)",
  "geocoding_precision": "DISTRICT_LEVEL_APPROXIMATE",
  "confidence": 0.0,
  "measurement_status": "NO_LAB_ASSAYS_AVAILABLE",
  "value_nature": "FACTUAL_ABSENCE",
  "audit_notes": "ยังไม่มีผลการตรวจวิเคราะห์ตัวอย่างน้ำทางห้องปฏิบัติการที่ได้รับการรับรองในจุดนี้"
}
```

## 5. การตรวจสอบความถูกต้องด้วยรหัสเข้ารหัส (Cryptographic Hash Manifest)

เพื่อป้องกันการแก้ไขข้อมูลโดยมิชอบ ข้อมูลสถิติและประวัติการตรวจสอบจะถูกสร้างรหัสตรวจสอบ (SHA-256 Checksum) ประจำชุดข้อมูล:
- **ชุดข้อมูลโรงงาน DIW (พ.ค. 2563):** `sha256:711b77d9cc8e449ba5c0cd4c617a9983...`
- **โครงข่ายลำน้ำหลักปราจีนบุรี (RID/DWR):** `sha256:4a8e91c78119df0e3c88b15fa42e1189...`

หากพบว่ารหัส Hash ไม่ตรงกับที่บันทึกไว้ในระบบ ระบบจะปฏิเสธการประมวลผลทันทีเพื่อรักษาความถูกต้องแท้จริงของข้อมูล
