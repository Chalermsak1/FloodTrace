# แหล่งกำเนิดข้อมูลและสายการแปรรูป (DATA PROVENANCE & LINEAGE)
**ขอบเขตระบบ:** แพลตฟอร์ม FloodTrace จังหวัดปราจีนบุรี  
**สถานะการตรวจสอบ:** ร่างฉบับตรวจสอบความจริงเพื่อการใช้งานจริง (PRODUCTION TRUTH AUDIT)  
**วันที่ตรวจสอบล่าสุด:** 2026-10-02  

---

> [!IMPORTANT]
> ### หลักการสำคัญ: LOCAL_IMPORT $\neq$ EXTERNAL_API
> ระบบ FloodTrace แยกแยะอย่างเด็ดขาดระหว่าง:
> 1. **ข้อมูลที่ดึงสดผ่าน External API อัตโนมัติ (`EXTERNAL_API`)** ซึ่งเชื่อมต่อกับแหล่งตรวจวัดจริงและอัปเดตตามรอบเวลา
> 2. **ข้อมูลที่นำเข้าจากไฟล์อ้างอิงทางการในระบบ (`LOCAL_IMPORT`)** เช่น แผนที่ลำน้ำ ทะเบียนหมู่บ้าน หรือข้อมูลประวัติโรงงานปี 2563
> 
> ห้ามเปลี่ยนสถานะ `LOCAL_IMPORT` ให้กลายเป็น `LIVE` หรือ `AUTOMATED_EXTERNAL_INGESTION` โดยเด็ดขาด

## 1. โครงสร้างเมทาดาตาแหล่งข้อมูลในฐานข้อมูล (Section 22 Database Source Metadata)

ทุกชุดข้อมูลและระเบียนที่ถูกจัดเก็บในระบบ จะต้องมีฟิลด์เมทาดาตากำกับความจริง 11 รายการ ดังต่อไปนี้:

| ฟิลด์เมทาดาตา | คำอธิบาย | ตัวอย่างค่าที่ใช้งานจริง |
|---|---|---|
| **`source_name`** | รหัสอ้างอิงแหล่งข้อมูลภายในระบบ | `thaiwater_rid_runoff`, `diw_industrial_waste` |
| **`organization`** | องค์กร/หน่วยงานผู้ผลิตข้อมูล | `สสน. / กรมชลประทาน`, `กรมโรงงานอุตสาหกรรม` |
| **`dataset`** | ชื่อชุดข้อมูลทางการ | `โทรมาตรระดับน้ำแม่น้ำปราจีนบุรี`, `ทะเบียนการจัดการของเสียอันตราย` |
| **`record_id`** | รหัสเฉพาะของระเบียนข้อมูล | `station_1405`, `fac_2563_0112` |
| **`source_timestamp`** | วันเวลาที่แหล่งข้อมูลต้นทางระบุหรือตรวจวัดได้ | `2026-10-02T19:00:00+07:00` |
| **`retrieved_at`** | วันเวลาที่ FloodTrace ทำการดึงหรือนำเข้าข้อมูล | `2026-10-02T19:15:02+07:00` |
| **`access_status`** | สถานะสิทธิการเข้าถึงข้อมูล | `PUBLIC_VERIFIED`, `LOCAL_REFERENCE` |
| **`license_status`** | สถานะสัญญาอนุญาตการเผยแพร่ | `OPEN_GOVERNMENT_DATA`, `OFFICIAL_REFERENCE` |
| **`data_classification`** | ระดับการจัดหมวดหมู่ข้อมูล | `MEASURED_FACT`, `HISTORICAL`, `STATIC_REFERENCE` |
| **`freshness_status`** | สถานะความสดใหม่ของข้อมูล | `FRESH`, `PERIODIC`, `HISTORICAL` |
| **`ingestion_mode`** | รูปแบบการนำเข้าข้อมูลสู่ระบบ | `EXTERNAL_API`, `LOCAL_IMPORT`, `INTERNAL` |

### หมวดหมู่ Ingestion Mode ที่ได้รับอนุญาต:
- **`EXTERNAL_API`**: ดึงอัตโนมัติจาก API ทางการของหน่วยงานภายนอก (เช่น สสน./ThaiWater)
- **`EXTERNAL_FILE`**: ดาวน์โหลดไฟล์ทางการจากภายนอกตามรอบเวลา
- **`LOCAL_IMPORT`**: นำเข้าจากไฟล์อ้างอิงทางการที่มีอยู่เดิมในเครื่อง
- **`INTERNAL`**: ข้อมูลที่สร้างจากระบบ FloodTrace เอง (เช่น รายงานประชาชน)
- **`TEST`**: ข้อมูลสำหรับชุดทดสอบ (แยกขาดจาก Production)
- **`DEMO`**: ข้อมูลสาธิต (แยกขาดจาก Production)

## 2. การจัดเก็บข้อมูลอนุกรมเวลาในอดีต (Section 18 Historical Time-Series Storage)

สำหรับแหล่งข้อมูลอนุกรมเวลา (Time-Series) เช่น ระดับน้ำและปริมาณน้ำฝน:
- **ห้ามเขียนทับข้อมูลเก่า (Do not overwrite historical records):** เมื่อมีข้อมูลตรวจวัดใหม่เข้ามา ระบบจะจัดเก็บลงในตารางแยกเฉพาะ:
  - `WaterLevelObservation` สำหรับระดับน้ำ
  - `RainfallObservation` สำหรับปริมาณน้ำฝน
- **ฟิลด์ที่บันทึกในทุกจุดเวลา:**
  - `station_id` (รหัสสถานี)
  - `source_timestamp` (เวลาที่ตรวจวัด)
  - `value` (ค่าที่วัดได้จริง)
  - `retrieved_at` (เวลาที่ระบบบันทึก)
  - ข้อมูลเมทาดาตาและ Provenance ครบถ้วน
- **ช่วงเวลาย้อนหลังที่ระบบรองรับ:**
  - **`24H`**: 24 ชั่วโมงย้อนหลัง (ความละเอียดระดับชั่วโมง)
  - **`7D`**: 7 วันย้อนหลัง
  - **`30D`**: 30 วันย้อนหลัง
- **API สาธารณะ:**
  - `GET /api/public/stations/{station_id}/history?range=24h|7d|30d`
  - `GET /api/public/rainfall/{station_id}/history?range=24h|7d|30d`

## 3. วงจรการอัปเดตอัตโนมัติและการส่งสัญญาณ (Automated Refresh & DATA_UPDATED Event)

ระบบบริหารจัดการดึงข้อมูลอัตโนมัติผ่าน `SourceScheduler` ใน `apps/api/app/core/scheduler.py`:

```
┌──────────────────────┐
│ แหล่งข้อมูลภายนอก      │ (ThaiWater API)
└──────────┬───────────┘
           │ HTTPS GET (ทุก 15 นาที พร้อม Circuit Breaker)
           ▼
┌──────────────────────┐
│  SourceScheduler     │ ──> ตรวจสอบความถูกต้องของ Schema & ขจัดข้อมูลซ้ำ (Deduplication)
└──────────┬───────────┘
           │
           ├──────────────────────────────┐
           ▼                              ▼
┌──────────────────────┐       ┌──────────────────────┐
│ ฐานข้อมูล PostgreSQL │       │  Realtime Event Bus  │
│ - WaterLevelObs      │       │  (SSE Broadcast)     │
│ - RainfallObs        │       └──────────┬───────────┘
└──────────────────────┘                  │
                                          ▼
                               ┌──────────────────────┐
                               │ GET /realtime/events │
                               │ อีเวนต์: DATA_UPDATED│
                               └──────────────────────┘
```

### รายละเอียดเหตุการณ์ `DATA_UPDATED` (Section 17):
เมื่อแหล่งข้อมูลได้รับการอัปเดตสำเร็จ ระบบจะส่งสัญญาณ SSE ผ่าน `GET /api/v1/realtime/events`:
```json
{
  "event": "DATA_UPDATED",
  "data": {
    "source": "thaiwater_rid_runoff",
    "dataset": "โทรมาตรระดับน้ำแม่น้ำปราจีนบุรี",
    "area": "ปราจีนบุรี",
    "timestamp": "2026-10-02T19:15:02+07:00",
    "records_updated": 26
  }
}
```
*หมายเหตุ: ปราศจากข้อมูลส่วนบุคคล (No PII) และไม่มีข้อมูลลับ/กุญแจ API ใดๆ ทั้งสิ้น*

## 4. ตัวอย่างการไหลของข้อมูลในระบบ (Data Lineage Examples)

### ตัวอย่างที่ 1: โทรมาตรระดับน้ำสด (ThaiWater Real Telemetry)
1. **ต้นทาง:** สถานีตรวจวัด สสน./กรมชลประทาน $\rightarrow$ Ingestion Mode: `EXTERNAL_API`
2. **การดึงข้อมูล:** `SourceScheduler` เรียก `https://api-v3.thaiwater.net/.../waterlevel_load` ทุก 15 นาที
3. **การตรวจสอบ:** คำนวณ SHA-256 Payload Hash หากซ้ำกับระเบียนเดิมจะข้ามการเขียนซ้ำ (`duplicates_skipped`)
4. **การบันทึก:** บันทึกระเบียนประวัติ `WaterLevelObservation` พร้อมคงค่าเก่าไว้
5. **การแสดงผล:** แสดงค่าปัจจุบันและกราฟแนวโน้มบนแผนที่สาธารณะ พร้อมสถานะ "ข้อมูลล่าสุดที่ตรวจวัดได้"

### ตัวอย่างที่ 2: ข้อมูลอ้างอิงโรงงานอุตสาหกรรม (DIW Industrial Waste Reference)
1. **ต้นทาง:** ข้อมูลเผยแพร่ทางการของกรมโรงงานอุตสาหกรรม (18 พฤษภาคม 2563) $\rightarrow$ Ingestion Mode: `LOCAL_IMPORT`
2. **การจัดหมวดหมู่:** กำหนดเป็น `HISTORICAL` และระบุวันที่ชัดเจน 2020-05-18
3. **ข้อจำกัด:** ไม่มีการดึงสดจากภายนอก (`AUTOMATED_REFRESH = FALSE`)
4. **การแสดงผล:** กำกับป้ายชื่อชัดเจนว่า **"ข้อมูลประวัติทางการ (พฤษภาคม 2563)"** ห้ามแสดงว่าเป็นข้อมูลปัจจุบันเด็ดขาด

## 5. การตรวจสอบความถูกต้องด้วยรหัสเข้ารหัส (Cryptographic Integrity)

เพื่อรับประกันว่าข้อมูลจะไม่ถูกดัดแปลงแก้ไขในกระบวนการประมวลผล:
- ทุกคำขอและผลลัพธ์การนำเข้าถูกคำนวณ Checksum ด้วยอัลกอริทึม SHA-256
- รายงานภาคประชาชนถูกกำกับด้วยรหัสเฉพาะ และตัดข้อมูลส่วนบุคคลก่อนสร้างบันทึกสาธารณะ
