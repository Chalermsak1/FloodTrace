> [!IMPORTANT]
> ### หลักการทางวิทยาศาสตร์ที่ไม่สามารถประนีประนอมได้ (Non-Negotiable Scientific Principles)
> 1. **ระยะทางใกล้เคียง $\neq$ การปนเปื้อน (Proximity $\neq$ Contamination):** การที่โรงงานตั้งอยู่ใกล้แม่น้ำหรือพื้นที่น้ำท่วม ไม่ได้แปลว่ามีการปล่อยน้ำเสียหรือสารพิษลงสู่สิ่งแวดล้อม
> 2. **น้ำท่วมถึง $\neq$ การรั่วไหล (Flood Contact $\neq$ Release):** การที่น้ำท่วมล้นเข้าไปในบริเวณสถานประกอบการ มิได้พิสูจน์ว่ามีกากของเสียรั่วไหลออกสู่นอกโรงงาน
> 3. **น้ำไหลเชื่อมต่อกัน $\neq$ ความผิดทางกฎหมาย (Connectivity $\neq$ Guilt):** การจำลองว่าน้ำจากจุดหนึ่งสามารถไหลไปยังอีกจุดหนึ่งได้ ไม่สามารถนำไปชี้ความรับผิดทางแพ่งหรืออาญาได้
> 4. **ไม่มีการจัดอันดับโรงงานอันตราย (No Blacklist):** ระบบจะไม่สร้างการจัดลำดับความอันตรายหรือสร้างรายชื่อผู้ถูกกล่าวหา
> 5. **ต้องมีผลตรวจทางห้องแล็บเท่านั้น:** ข้อมูลการปนเปื้อนทางเคมีจำเป็นต้องได้รับการเก็บตัวอย่างตรวจวัดจริงทางห้องปฏิบัติการเท่านั้น หากไม่มีผลตรวจ ระบบจะแสดงสถานะเป็น **`INSUFFICIENT DATA (ข้อมูลไม่เพียงพอ)`** เสมอ
> 6. **ไม่มีการสร้างข้อมูลทดแทน (No Synthetic Fallback):** หากสถานีโทรมาตรหรือดาวเทียมไม่มีข้อมูล ระบบจะส่งสถานะ `NO_DATA` หรือ `UNAVAILABLE` อย่างซื่อตรง ไม่สร้างค่าตัวเลขจำลองเพื่อความสวยงาม

## 1. กรอบแนวคิด แหล่งกำเนิด $\rightarrow$ เส้นทาง $\rightarrow$ ตัวรับผลกระทบ (Source-Pathway-Receptor)

ระบบจัดโครงสร้างการวิเคราะห์ตามหลักการสากลทางวิทยาศาสตร์สิ่งแวดล้อม (S-P-R Framework):

```
┌─────────────────────────┐       ┌──────────────────────────┐       ┌────────────────────────┐
│     แหล่งกำเนิด (SOURCE)  │       │     เส้นทาง (PATHWAY)      │       │ ตัวรับผลกระทบ (RECEPTOR) │
│ ข้อมูลประวัติโรงงาน ปี 2563│ ────> │ โครงข่ายลำน้ำหลัก DWR    │ ────> │ ชุมชน / หมู่บ้าน (DOPA) │
│ จุดที่ได้รับแจ้งเหตุชุมชน│       │ ขอบเขตพื้นที่น้ำท่วมขัง     │       │ พื้นที่เกษตรกรรม        │
│ ผลตรวจแล็บ คพ. (ถ้ามี)   │       │ ทิศทางการไหลบนผิวดิน     │       │ รพ.สต. / โรงพยาบาล     │
└─────────────────────────┘       └──────────────────────────┘       └────────────────────────┘
                                               │
                                               ▼
                               ┌───────────────────────────────────┐
                               │ ลำดับความสำคัญในการเฝ้าระวัง        │
                               │ (MONITORING PRIORITY)             │
                               │ จุดที่ควรส่งเจ้าหน้าที่ไปตรวจก่อน │
                               └───────────────────────────────────┘
```

- **มันทำงานอย่างไร:** ระบบประเมินความสัมพันธ์ทางภูมิศาสตร์ระหว่างจุดที่ตั้งที่มีบันทึกทางการ โครงข่ายลำน้ำ และพื้นที่เปราะบาง เพื่อประเมินว่าหากเกิดน้ำท่วมล้น มวลน้ำจะเดินทางไปสู่บริเวณใด
- **มันไม่ได้หมายความว่าอะไร:** **มันไม่ได้แปลว่ามีการปนเปื้อนเกิดขึ้นแล้ว** แต่มันคือการคำนวณ **"ลำดับความสำคัญในการส่งทีมลงตรวจ (Monitoring Priority)"** เพื่อให้หน่วยงานราชการจัดสรรทรัพยากรได้อย่างมีประสิทธิภาพสูงสุด

## 2. การจำแนกคำศัพท์ตามสถานะความจริง (Section 19 Real-Time vs Automated Terminology)

เพื่อให้เกิดความแม่นยำทางวิชาการและไม่ชี้นำประชาชนผิดพลาด ระบบใช้คำนิยามดังนี้:

| คำศัพท์ทางการ | ความหมายทางเทคนิค | ตัวอย่างใน FloodTrace |
|---|---|---|
| **`REAL_TIME`** | แหล่งข้อมูลต้นทางตรวจวัดและอัปเดตแบบต่อเนื่องทันที (Continuous Sensor Stream) | ไม่มี (เนื่องจากสถานีโทรมาตรส่วนใหญ่ตรวจวัดเป็นรอบชั่วโมง) |
| **`HIGH_FREQUENCY`** | แหล่งข้อมูลมีการตรวจวัดและปรับปรุงค่าอย่างสม่ำเสมอทุกชั่วโมง | สถานีวัดระดับน้ำและปริมาณฝน สสน. |
| **`AUTOMATED`** | ระบบ FloodTrace ดึงข้อมูลอัตโนมัติจากภายนอกตามรอบเวลา โดยไม่ต้องใช้คำสั่งมนุษย์ | `SourceScheduler` ดึง ThaiWater ทุก 15 นาที |
| **`PERIODIC`** | ข้อมูลต้นทางมีการปรับปรุงเป็นรอบระยะ (เช่น รายสัปดาห์ หรือรายเดือน) | สถิติทะเบียนประชากร หรือรายงานสรุปประจำเดือน |
| **`HISTORICAL`** | ข้อมูลในอดีตที่ยุติการอัปเดตแล้ว แต่ยังใช้เป็นค่าอ้างอิงฐานได้ | ทะเบียนโรงงานของเสียอันตราย กรมโรงงานฯ (18 พ.ค. 2563) |
| **`STATIC_REFERENCE`** | ข้อมูลอ้างอิงเชิงพื้นที่ที่ไม่ค่อยเปลี่ยนแปลง | โครงข่ายเส้นลำน้ำ DWR, ทำเนียบหมู่บ้าน DOPA |

## 3. ข้อมูลโรงงานของเสียอันตราย DIW (Section 8 Industrial Baseline)

- **สถานะชุดข้อมูล:** ข้อมูลที่ FloodTrace ได้รับสิทธิใช้งานคือ **ชุดข้อมูลทางการ ณ วันที่ 18 พฤษภาคม 2563 (112 ระเบียน)**
- **การจัดประเภทข้อมูล:** กำหนดสถานะเป็น **`HISTORICAL`** โดยเด็ดขาด
- **การแสดงผลต่อสาธารณะ:** แสดงป้ายกำกับชัดเจน: **"ข้อมูลประวัติทางการ (พฤษภาคม 2563)"**
- **ข้อห้ามเด็ดขาด:** ห้ามระบุหรือชี้นำว่าเป็น "สถานะโรงงานในปัจจุบัน" หรือ "ข้อมูลสด"

## 4. สถานะแหล่งข้อมูลที่ถูกปิดกั้น (Section 11-14 Blocked Sources Policy)

หากแหล่งข้อมูลยังไม่ได้รับอนุญาตหรือไม่มีกุญแจ API ทางการ:
- **GISTDA Disaster Portal:** ปิดกั้น (`PRODUCTION_BLOCKED`) ไม่สร้างรูปหลายเหลี่ยม (Polygons) น้ำท่วมเท็จขึ้นมาเอง
- **TMD Forecast:** ปิดกั้น (`PRODUCTION_BLOCKED`) ไม่ดึงพยากรณ์จากแหล่งอื่นมาสวมรอย
- **PCD Water Quality:** ปิดกั้น (`PRODUCTION_BLOCKED`) แสดงสถานะไม่มีผลตรวจแล็บอย่างซื่อตรง

## 5. การจำลองโครงข่ายลำน้ำ (Hydrological Reach Tracing)

- **ฐานข้อมูล:** โครงข่ายลำน้ำทางการจากกรมทรัพยากรน้ำ (DWR Waterways) ที่นำเข้าไว้ในระบบ
- **การคำนวณ:** ใช้ Directed Graph Traversal วิเคราะห์เส้นทางต้นน้ำ (Upstream) และปลายน้ำ (Downstream)
- **ข้อจำกัด:** เป็นการวิเคราะห์การเชื่อมต่อทางชลศาสตร์ตามธรรมชาติ ไม่สามารถสะท้อนผลจากคันกั้นน้ำชั่วคราวหรือเครื่องสูบน้ำเคลื่อนที่ได้
